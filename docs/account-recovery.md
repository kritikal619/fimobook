# 계정 찾기와 비밀번호 재설정

- 로그인 화면에서 `아이디 찾기`와 `비밀번호 재설정`에 접근한다.
- `/find-id`: 확정된 감독명과 일치하는 계정의 가입 이메일을 일부 가려 보여준다. 감독명을 기준으로 대소문자만 다른 여러 계정이 있으면 결과를 노출하지 않는다. 이메일 전체나 Google 연동 여부는 공개하지 않는다.
- `/forgot-password`: 가입 이메일로 복구 안내를 보낸다. 계정 유무에 관계없이 같은 안내를 보여준다. Google로만 가입한 계정에는 로그인 안내를 보내며 별도 비밀번호를 만들지 않는다.
- `/reset-password/<token>`: 메일의 링크로 새 비밀번호와 확인을 입력한다. 8~128자까지 허용하며 자동 로그인하지 않는다.

## 설정과 적용

기존 인증 메일의 `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USE_TLS`, `MAIL_USE_SSL`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_DEFAULT_SENDER` 설정을 그대로 사용한다. 실제 발송에는 메일 계정 설정이 필요하며 메일 계정이 없으면 복구 요청 화면에서 서비스 이용 불가 안내를 표시한다. 링크는 요청 Host 대신 `PUBLIC_BASE_URL`로 생성한다.

`User.session_token`과 `account_recovery_throttle` 테이블을 추가한다. 현재 SQLite 앱에서는 시작 시 `_ensure_local_schema()`가 누락된 구조를 추가한다. Alembic 사용 환경에는 `e6c840d39a12` 마이그레이션도 제공한다. 기존 계정은 nullable 세션 토큰을 유지하므로 초기 적용만으로 로그아웃되지 않는다.

## 복구 동작

서명 링크의 유효기간은 30분이다. 이메일·비밀번호 해시·세션 토큰·Google 연결 상태에 링크를 결합한다. DB의 기존 상태를 조건으로 한 번만 변경하므로 같은 링크로 동시에 변경해도 한 요청만 성공한다. 비밀번호가 바뀌면 이전 복구 링크와 모든 이전 로그인·로그인 유지 쿠키가 무효화된다.

이메일을 아직 인증하지 않은 일반 계정도 메일의 링크로 소유권을 증명한 후 비밀번호를 변경하고 이메일 인증을 완료할 수 있다. Google 감독명 확정이 끝나지 않은 계정은 Google 가입 절차를 통해 복구한다.

CSRF와 기존 reCAPTCHA를 적용한다. 복구 요청은 공통 IP당 15분에 10회, 기능별 입력값당 1시간에 5회로 제한하고, 비밀번호 안내 메일은 같은 이메일당 60초에 1회로 제한한다. 전체 복구 요청은 1시간에 1,000회로 제한한다. SQLite의 원자적 upsert로 여러 worker가 제한을 공유하며 만료된 항목은 요청 시 삭제한다. IP와 이메일·감독명은 HMAC으로 저장한다. 제한에 걸린 요청도 앞선 공통 한도는 차감한다.

복구 화면은 캐시와 검색 색인을 차단하고 외부 referrer를 보내지 않는다. 복구 페이지에는 GA4와 Google One Tap을 로드하지 않는다. 애플리케이션 메일 실패 로그에는 이메일과 링크를 기록하지 않는다. 웹 서버 접근 로그는 서버 운영 설정의 영향을 받으므로 복구 URL에 대한 로그 접근도 제한해야 한다.

Python과 Jinja 템플릿 구문을 확인했다. 테스트 실행과 실제 메일 발송은 수행하지 않았다.
